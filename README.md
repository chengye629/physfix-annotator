# PhysFixBench 视频标注

基于 PhysFixBench / Physion-300 的中文视频标注网站。只收录**明显、客观、可重复观察的物理问题**，不确定和模棱两可的现象不进入有效问题集。

纯静态网站，没有安装依赖、登录或数据库要求。支持 GitHub Pages，优先播放网站同域的原视频镜像，保留 Hugging Face 原站作为备用线路。

## 视频加载

- `videos/` 保存原视频文件，按上游 SHA-256 校验，逐字节相同，没有压缩、降分辨率、抽帧或重编码。镜像索引见 `data/video-manifest.json`。
- 当前视频使用 `preload="auto"` 渐进加载；当前视频可连续播放后才后台预载下一条未完成任务。
- 已预载的视频使用内存缓存直接播放，最多保留 3 条、总计 40 MiB；同时利用浏览器 HTTP 缓存。切换任务会中止未完成的预载，避免与当前播放争抢带宽。浏览器启用节省流量时不自动预载。
- 「自动线路」优先同域镜像，连接失败或持续缓冲时尝试原站。也可以手动切换「网站线路 / HF 原站」。同一条切换线路会保留播放位置与速度。
- 缓存只包含视频；原有标注员身份、草稿和已完成标注的保存格式不变。
- 初始任务索引优先加载体积更小的 gzip 文件，并在浏览器解压；不支持的浏览器自动回退原始 JSONL。

## 标注流程

1. 设置自己的标注员昵称，选择任务分组（每组 50 条），独立观看视频。300 条数据全部提供，没有预先把候选草稿当成人工确认结果。
2. 选择「明确有物理问题 / 无明显物理问题 / 不确定 / 无法播放」。没有默认判断。
3. 明确有问题时，逐条填写类别、起止秒数、可见异常和对应的正确表现，以及需要保持不变的内容。必须确认可见、客观、排除合理解释这三项标准。
4. 点击「保存并下一条」提交。编辑会自动保存为草稿，草稿不计入已完成；修改已完成记录后，需重新点击保存。
5. 定期「导出备份」，把 JSON 文件交给负责人。通过「我的记录」可导出只含有效问题的研究数据。

参考草稿默认折叠；手动采用文字不会预选判断，也不会自动勾选质量确认。源数据的明显/细微标签只作背景信息，不决定人工最终判定。

步进按钮按所选 24 / 30 / 60 fps 移动时间，并非自动识别源视频帧率。时间戳为播放器时间，不是精确解码后的帧编号。

## 多人回收与合并

- 所有个人进度保存在浏览器 `localStorage`，不向服务器上传。网站是公开入口，个人标注不会跨浏览器实时同步。
- 每个浏览器生成独立标注员 ID。多人请使用各自浏览器与不同昵称。同一浏览器同时只支持一个身份；不要共用浏览器做独立复核。
- 换设备继续个人工作：在新设备使用「恢复个人备份」，这会恢复原身份并替换新设备中的个人进度。
- 负责人打开「结果汇总」，多选导入各人的**个人备份**。有效问题集和汇总导出不是个人备份，不用于恢复。
- 同一标注员同一样本的重复导出按最新时间去重。新草稿会撤回旧的已完成判断，防止修改后的记录仍被计票。
- 默认最少 2 位独立标注员全部认为「明确有物理问题」且均通过证据校验，才进入一致问题集。可调整人数门槛；任意不同判定均标为分歧并排除。
- 一致表示「有明确物理问题」这一判定一致，不代表修复细节已仲裁。汇总导出保留所有人的问题描述和修复要求，不自动选择任一人的文字作为最终答案。
- 汇总导入只在当前页面会话中保留，关闭或刷新页面前请导出。
- 清理浏览器数据、隐私模式和存储限额可能导致本机保存不可用。界面会提示保存失败；请及时导出备份。

导出数据结构及判定规则见 `core.js`。`personal_backup` 包含草稿和已完成记录，`effective_problem_set` 仅包含个人有效问题，`merged_review` 包含去重后的全部投票，`consensus_problem_set` 仅包含符合人数与一致性要求的样本。

## 本地运行与验证

需要 Node.js 22 或更新版本，无第三方依赖：

```sh
node scripts/serve.mjs
# 打开 http://127.0.0.1:4173
node --test tests/core.test.mjs tests/video-delivery.test.mjs tests/dataset-loader.test.mjs
```

请通过 HTTP 服务访问，不要直接双击 HTML，因为浏览器可能限制加载数据文件。

快捷键：`1 / 2 / 3` 选择主要判断；`,` / `.` 步进；`Alt + ← / →` 切换视频；`Ctrl / Cmd + Enter` 保存；`?` 打开指南。在输入框中不会触发判断或导航快捷键。

任务链接支持 `?group=1` 至 `?group=6` 分配分组，`?sample=T1_01334` 直达某条。播放器下方可以复制当前任务链接。

## GitHub Pages

仓库推送到 `main` 后，在仓库 Settings → Pages → Build and deployment 中选择 **Deploy from a branch**，分支选择 `main`，目录选择 `/ (root)` 并保存。GitHub 的内置 Pages 流程会发布网站。`.nojekyll` 让静态文件保持原样。更新前可运行上述规则测试，再推送到 `main` 触发重新部署。

没有后端密钥、访问令牌、外部字体或分析追踪。静态资源采用相对地址，兼容 GitHub Pages 仓库子路径。

## 数据来源与使用限制

- 数据：[SiyuanMaCS/PhysFixBench](https://github.com/SiyuanMaCS/PhysFixBench)，源提交 `fcef4a429c9061fa36db64f3213b8fbc37b121bf`；本地保留原始 300 行 JSONL，不改写源标注。
- 视频：[HuggingFriends/PhysFixBench](https://huggingface.co/datasets/HuggingFriends/PhysFixBench/tree/main/videos)，300 个视频路径逐一与索引核对。网络或源站访问策略变化可能影响播放，网站提供单独的播放故障判定。
- 交互流程参考：[MLLM-as-Embodied-World-Judge-Annotation](https://github.com/SiyuanMaCS/MLLM-as-Embodied-World-Judge-Annotation)：标注员身份、视频观察、证据填写、保存后下一条和个人进度。本仓库界面和逻辑独立实现，没有连接或复用其在线后端。
